Overview

How design images are uploaded, versioned, and progressed through review inside Design → Listing Images. Every image lives in a per-product slot, is stored automatically in the client's Google Drive, keeps a full version history, and moves through a six-stage status workflow from Not Started to Live.

10
Image slots per product — MAIN + PT01–PT09
6
Statuses — Not Started → In Progress → In Review → Approved → Live → Discontinued
V01+
Versions per slot — every re-upload creates a new version, history is kept

Before You Start — Key Concepts

Where it lives

Open Design → Listing Images, choose a client, then pick a variation. You'll see a grid: one row per product, one column per image slot.

The 10 slots

Each child product has ten image slots. MAIN is the hero image; PT01–PT09 are the additional gallery images.

Parent vs. child rows

A parent row is a header only — it groups a variation and shows the product count. It holds no images and has no upload cells or status controls.

Child rows are the individual products (by ASIN). Only child rows have the ten upload slots. This is where all uploading happens.

Uploading an Image

1
Open the client and variation
From Design → Listing Images, select the client, then open the variation whose products you want to work on. The grid loads with a row per product and a column per slot.
2
Find the right slot
Locate the child product row (by ASIN) and the slot column you want — MAIN for the hero image, or PT01–PT09 for a gallery image. Empty slots show a dashed upload box; filled slots show a thumbnail.
3
Add the image
Either way works:
Click to browse
Click the upload cell and pick a file from your machine.
Drag & drop
Drag an image file directly onto the cell.
4
The file syncs to Google Drive Automatic
The image is uploaded into the client's Drive under Graphics / Listing Images / {Product ID} with a versioned filename. The subfolder for that product is created on the first upload — you don't create it manually. A confirmation appears when the upload finishes.
5
A version is created Automatic
Each upload becomes a new version for that slot (V01, V02, …). The newest version is shown in the grid; the rest are kept in the version history. New images start at Not Started until you set a status.

Version Control

Every slot keeps a full history. Re-uploading never overwrites the previous image — it adds a new version, so you can always look back or roll forward.

How versions are numbered

Versions increment sequentially: V01, V02, V03… If you delete a version, its number is freed and the gap is back-filled on the next upload — so numbering stays contiguous with no holes.

Open the version history

Click the version badge (e.g. V01) on a thumbnail to open the history popover. There you can see every version's thumbnail, number, status, and date, with the latest marked current.

Add, switch, or delete

Add a version by uploading again to the same slot. Roll back by setting an older version's status to Live. Delete a version to remove it permanently (a hard delete — its number is then reused on the next upload).

V01 → re-upload → V02 → re-upload → V03 · delete V02 → next upload back-fills → V02

The 6-Status Workflow

Each version carries a status that shows where it is in the review and publishing process. Set it from the status chip under a thumbnail (newest version), from the version history popover (any specific version), or in bulk from the row's status control.

Status What it means / when to use it
Not Started Default for a freshly uploaded image. Work on it hasn't begun yet.
In Progress The designer is actively working on the image.
In Review Submitted for review or client approval — awaiting feedback.
Approved Signed off and ready, but not yet published to the marketplace.
Live Currently published on Amazon. Only one version per slot can be Live at a time.
Discontinued Retired — was previously Live and has since been replaced.
Not Started → In Progress → In Review → Approved → Live

Going Live — Automatic Behavior

Marking a version Live
  • ✅The chosen version becomes the active image for that slot.
  • 🔁Any other version of the same slot that was Live is automatically set to Discontinued.
  • 1️⃣This guarantees exactly one Live version per slot — no manual cleanup needed.
What Discontinued means
  • 🗂️The version is retired but not deleted — it stays in the history.
  • 👁️Discontinued versions can be hidden or surfaced using the status filters at the top of the grid.
  • ↩️You can promote a discontinued version back to Live; the current Live one then becomes Discontinued in turn.
V02 Live → set V03 to Live → V03 Live + V02 Discontinued
📁 Drive is the source of truth for the files themselves. Uploads, new versions, and deletions all sync to the client's Google Drive automatically. The status workflow tracks review state inside the hub; it does not change what's actually published on Amazon until the listing is pushed live.

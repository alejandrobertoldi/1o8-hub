Overview

How a client's Amazon Brand Story is built, versioned, and moved through review inside Design → Brand Story. Unlike Listing Images (one image per product slot), the Brand Story is per-brand: one story spans the whole catalog. Each version is a full draft — background images, content modules, copy, and ASINs — stored in the client's Google Drive, with a manual status workflow.

19
Modules max per version — 4 types: ASIN Showcase, Focus Image, Logo & Description, Q&A

Before You Start — Key Concepts

Where it lives

Open Design → Brand Story, then pick a client. You'll see that client's versions stacked as cards — newest work at the top, an "add another version" card at the bottom. There is one Brand Story per client; everything here applies to the whole brand, not a single ASIN.

Per-brand, not per-product

A Brand Story is a single A+ module set that Amazon shows across the brand's listings. You build it once per client. (Contrast Listing Images, where every product/ASIN has its own image slots.)

The Screenview starts a version

A version is created by uploading a Screenview — the reference mock/screenshot of the finished story. That upload creates the version and its Drive subfolder. A version with no screenview shows as incomplete.

The 4 module types

Each version holds up to 19 modules, in any order. There are four types:

ASIN & Store Showcase
Focus Image
Logo & Description
Q&A

Creating a Version

1
Open the client
From Design → Brand Story, choose the client. Existing versions load as cards; if there are none you'll see "No versions yet — upload the screenview image to start".
2
Upload the Screenview image
Click Upload Screenview image on the bottom card and pick the reference mock (PNG, JPEG, or WebP). This creates the next version — numbered V01, V02, … — named {client}_Brandstory_V##.
3
A Drive subfolder is created Automatic
The version gets its own folder in the client's Google Drive, linked from the card header (Link to Drive folder). You don't create it manually. The new version starts at Not Started.
4
The editor opens under the screenview
The version card shows the screenview preview (with a Replace button) and, below it, the module editor where you build the story.

Building the Brand Story

Inside a version you set the brand backgrounds, then add and fill modules. Every text field shows a live character count; limits are enforced when you save and vary by module type.

Background images

Upload a desktop and a mobile background (PNG/JPEG/WebP), each with its own alt text. These are the canvas the Brand Story renders on.

Brand ASIN & Store Showcase

Up to 4 ASIN cards — each with an ASIN, a product image, and alt text — plus a Brand Store ID to link the storefront.

Brand Focus Image

One focus image with a headline, body copy, and image alt text.

Brand Logo & Description

The brand logo image with a headline, body description, and alt text.

Brand Q&A

Up to 3 question/answer pairs. Four preset questions are offered (e.g. "How did we get our start?", "What makes our products unique?") — use them or write your own.

🖼️ Images are PNG, JPEG, or WebP only and sync to the version's Drive subfolder as you upload. Add modules up to the limit of 19; reorder and remove them as the story takes shape.

AI Alt Text

An optional Edit suggestion pill sits next to an orange generate pill with a Sparkles icon. The suggestion is guidance for the model, not the alt itself.

Version header

Edit suggestion sits next to Generate Alt Text and writes alt text for every image in that version — both backgrounds and all module/ASIN images — then saves them in one pass. Leave the suggestion empty to generate without sending the current alt. Fill it to regenerate; the suggestion is sent with the current alt.

Module header

The Backgrounds card and each image module card use the same Edit suggestion + orange Alt text generate control. Backgrounds generate desktop and mobile alts together; a module run covers that card only (including every ASIN image on a showcase). Q&A modules have no image alt.

Alt fields

Each alt is a three-line textarea (100 characters). Desktop and mobile backgrounds keep separate alts. An orange copy icon on the alt label copies the current value. Edit suggestion does not have a copy icon.

When to use a suggestion

Type a revision request — a missing product name, a detail to include — then generate. Review the result in the alt field before moving the version through review.

Master Files

Upload master files manually to Drive

Master files are the large working/source files behind the story. Because they're too big to upload through 1o8 Hub, they're added manually in Google Drive — drop them straight into the version's Master Files folder (the …_Master_Files subfolder created alongside each version). The hub tracks the story's status and modules, but the master files themselves live only in Drive.

The Status Workflow

Each version carries a status, set from the status dropdown in that version's card header. It tells the team where the version sits in review and publishing.

Status What it means / when to use it
Not Started Default for a freshly created version. Work hasn't begun.
In Progress The story is actively being built — modules, copy, images.
In Review Submitted for review or client approval — awaiting feedback.
Approved Signed off and ready, but not yet published to Amazon.
Live The version currently published as the brand's A+ Brand Story.
Discontinued Retired — kept for history after being replaced.
Not Started → In Progress → In Review → Approved → Live
Status is manual
  • ✋You set each version's status by hand from its header dropdown. There are no automatic transitions.
  • ⚠️Marking one version Live does not auto-discontinue the others — unlike Listing Images. If two versions both read Live, that's on you to fix.
Removing a version
  • 🗑️Remove version (header button) deletes the version, all its modules, and the entire Drive subfolder. You'll be asked to confirm.
  • ↩️There's no undo — to roll back, keep the older version instead of deleting it and set it Live.
📁 Drive is the source of truth for the files themselves. Screenviews, backgrounds, and module images sync to the version's Google Drive subfolder as you work in the hub; master files are uploaded to Drive directly. The status workflow tracks review state inside the hub; it does not push the story to Amazon on its own.

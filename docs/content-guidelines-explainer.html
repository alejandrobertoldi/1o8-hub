ContentGuidelines

A 4-tier cascade that lets editors set messaging context at any level of the product hierarchy — resolved field-by-field at generation time.

01 — Tier hierarchy

Four tiers, one cascade

Higher tiers win. Listing is closest to the product; Brand is the global baseline.

Listing Per-ASIN override master.content_guidelines Highest
Group Variation group variation_groups.content_guidelines ↑ 2nd
Variation Variation defaults variations.content_guidelines ↑ 3rd
Brand Brand voice baseline seo_projects.brand_guidelines (text) Lowest
02 — Resolution mode

Field-by-field, not all-or-nothing

Each of the 5 fields independently picks the highest tier where it's set. A tier doesn't have to fill every field to contribute.

Old behaviour (v1): entire tier wins — if the group had any content, the group's object was used whole, discarding everything from variation/brand.
New behaviour (v2): each field is resolved independently — a listing can override just messagingAngle while inheriting keyFeatures from the group.
Field Type What it controls Example value
messagingAngle string One-liner editorial direction for Claude "Lead with sleep benefits, not fragrance"
targetAudience string Who this product is for "Adults 25–45 seeking better sleep"
keyFeatures string[] Key selling points to emphasise ["vegan formula", "dermatologist tested"]
doList string[] Writing rules — things to include ["Use sensory language", "Reference bedtime routines"]
dontList string[] Writing rules — things to avoid ["Avoid price comparisons", "Don't mention competitors"]

04 — Resolution algorithm

Step-by-step at generation time

Runs inside resolveGuidelinesFieldByField() in src/lib/variation-guidelines.ts

1

Load listing guidelines

For each ASIN in the batch, fetch master.content_guidelines by ASIN code. Returned as listing_guidelines in the S1 intake payload.

2

Look up group guidelines

Match the ASIN's variation_group string against the variation's group list loaded at S1 intake.

3

Use variation defaults as fallback

The variation's content_guidelines are the last structured tier — loaded alongside groups in S1.

4

Per-field winner selection

For each of the 5 fields: use the value from the highest tier where it is non-empty. Empty string and empty array both count as "not set".

5

Render into Claude prompt block

The resolved object is formatted by renderGuidelinesBlock() and appended after the brand guidelines section in the S6 generation prompt.

05 — Where to edit

Entry points

Guidelines can be set from two places in the app.

Guidelines Hub

Single page showing the full hierarchy for a client. Edit any tier without leaving the page. Best for batch setup.

/guidelines?client=AAC

Variation Builder

The existing variation page. Group guidelines are on the Guidelines tab of each group card; variation defaults are in the collapsible at the top.

/variations/[id]
Group Variation

Brand Guidelines Page

Read-only overview of all variation guidelines for a client. Links back to the variation builder to edit. No listing tier shown here.

/clients/[code]/brand-guidelines
Read-only

SEO Generate (automatic)

No manual editing here. Guidelines are resolved automatically from the 4 tiers and injected into the Claude prompt at S6 generation time.

/seo/[id]/seo
Auto-resolved
Key rules: Array fields (keyFeatures, doList, dontList) are picked wholesale from the winning tier — arrays are not merged across tiers. · Setting a field to empty string / empty array at a higher tier does not override a lower tier; it simply means "not set here, fall through". · To actively clear a field, the field must remain absent (null) in the JSONB — not set to an empty value.

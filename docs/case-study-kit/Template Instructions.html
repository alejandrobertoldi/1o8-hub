Seller Central Case Studies — Template Instructions

Detailed Case Study Template.html · 14 slides  ·  High Level Case Study Template.html · 5 slides  ·  1920×1080 · market·foundry brand look

1 · What this template is

Two sibling formats sharing one visual language (slate teal, charcoal cards, orange accent, Outfit):

  • Detailed / Granular — 14 slides. The deep dive: monthly sales chart, product mix, demand curve, paid media by channel, and four creative slides.
  • High-Level — 5 slides. The executive summary: Cover (headline + 3 KPI chips + client card), The Challenge (start vs target), The Results (six proof points), The Approach (five pillars), The Creative (brand story + 9-tile listing grid + A+ + storefront, orange CTA band).

Fill rules, voice, charts and image-slot behaviour below apply to both; chart-drawing (§5) applies to the detailed deck only. Pick High-Level for prospects and quick shares; Detailed for QBRs and case-study deep dives.

Figure banding (High-Level only). Private absolute $ figures — revenue, ordered sales, ad-attributed sales, spend, ASP, starting-point sales — never show real numbers: band them as "Low/Mid/High N-Fig" (e.g. Mid 7-Fig). Percentages, ratios (ROAS, growth multiples), impression/unit counts and module/ASIN counts stay real. Where a $ context line would leak a figure, swap it for a ratio (e.g. "on $28.5K spend" → "1.3× blended ROAS"). The Detailed deck is internal/QBR-facing and keeps exact figures. It is a single self-contained HTML file (plus assets/image-slot.js for drag-and-drop image slots). Every client value is written as a bracketed placeholder like [CLIENT NAME] or $[0.0]M — fill every bracket, drop in creative assets, and the deck is done.

Navigation: arrow keys, click, or swipe. Slides are <section class="slide" data-label="…"> children of the deck stage; the file scales itself to any window.

3 · Duplication workflow (per new client)

  1. Copy the file. Duplicate Case Study Template.html → <Client> - Seller Central Case Study.html. Never edit the template directly.
  2. Rename slot ids. Global find-replace id="tpl- → id="<client-slug>- (e.g. id="pura-). Slot ids must be unique per deck or dropped images will collide across decks.
  3. Pull the data. Twelve months (or engagement period) from Seller Central + Sponsored Ads reporting: monthly ordered sales & units; sessions, page views, CVR (unit-session rate), Buy Box %; top products by sales and units; ad spend / revenue / clicks / impressions / orders by campaign type by month.
  4. Fill every bracket. Search for [ until none remain (the SVG thumbnail block at the top too).
  5. Redraw the three SVG charts (see §5).
  6. Fill the image slots — drop files or paste Drive links — then bake to committed files before final export (see §6).
  7. Update page numbers only if slides were added/removed (footers read NN / 14).
  8. QA pass: every slide, no placeholder text, no clipped charts, honest numbers.

4 · Voice & numbers

  • Headlines are short and declarative; the accent color (--c-yellow, orange #FF751F) carries the key number or phrase.
  • Round display values ($64.6K, 5.2×, 98.9%); cite one exact total in the Sales Growth body copy.
  • Be honest with unflattering metrics (launch ACOS etc.) — frame as investment phase, don't hide.
  • Every stat must come from real reporting. No invented numbers, ever.

5 · Redrawing the SVG charts

Three charts are hand-drawn SVG: monthly sales bars (slide 06), cumulative demand curve (slide 08), and two spend/sales lines (slide 09). Each has a fixed plot area; map values linearly.

Slide 06 — bars

viewBox 0 0 880 340 · baseline y=280 · top gridline y=40 (=axis max)
bar height = value / axisMax × 240 ;  y = 280 − height
12 bars: width 44, first x=74, pitch 65.85
Set the three y-axis labels to round values ≥ the max month.

Slide 08 — cumulative line

viewBox 0 0 880 340 · plot y 40–250 (210px) · x from 60 to 860, 11 equal steps
y = 250 − cumValue / axisMax × 210 ;  close the fill path to y=250.

Slide 09 — spend vs sales lines

viewBox 0 0 880 300 · plot y 40–240 · x 50→860, 11 steps
Orange = sales, teal = spend, one shared max per card. Dot marks the peak point.

6 · Image slots — the rules that matter

Slots are <image-slot> elements. Three ways to fill one: drag a file onto it, click Browse file, or click Paste Drive link (Drive logo pill) and paste a Google Drive share link or any direct image URL — paste auto-submits. Share Drive files to the marketfoundry.agency domain ("anyone in this domain with the link") — public sharing is not needed; images load for anyone signed into their work Google account. A filled slot shows Replace / Edit / Delete controls on hover (Edit = pan/zoom reframe; Delete clears the drop and reveals any baked src). Key attributes: fit="cover|contain|width", align="top", shape/radius, placeholder, and src for a committed file.

The workflow: draft with Drive links → bake → export. Reports are drafted internally (all image handling by marketfoundry.agency users, domain-shared Drive links — short URLs that never hit the persistence cap). Before sharing anything externally, bake every image to a committed asset (e.g. assets/<slug>-li-3.webp, wired via the slot's src): Drive links only render for signed-in domain users, so an unbaked deck looks broken to clients. Dropped files (not links) live in a hidden state file with a size cap — bake those too and clear the state file. Then export the shareable PDF/PPTX from the baked deck.
  • Storefront slots use fit="width" align="top" — full-page screenshots show from the top and crop at the bottom.
  • A+ stacks use fit="cover" in fixed 1200/492 frames so modules butt flush.
  • Cover hero / logo / brand story use fit="contain" — never crop brand art.
  • Recommended native sizes: A+ modules 1200–1464px wide; brand story banner ~1464×625; listing images square ≥1000px; storefront full-page captures ~3000px wide.

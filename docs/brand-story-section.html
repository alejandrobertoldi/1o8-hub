BrandStory

The Brand Story section drives the Amazon Storefront brand-story content per client. Two surfaces: a landing card grid (one card per active client) and a per-client detail page with a per-version editor.

01 · Surfaces
RoutePurpose
/design/brand-story Landing grid. One card per active client. Shows the winning version's screenview thumbnail, status, version label, last update.
/design/brand-story/[clientIdCode] Per-client detail. Lists every V## for that client. Per-version editor: modules (1..19), backgrounds, screenview asset.
02 · Landing card
Cards surface "what is this client's brand-story situation right now?" at a glance. Cover = screenview of the winning version (object-contain so the full image fits). Meta = name, V##, time, updated-by, code. Footer = status selector that writes through to the underlying version.

03 · Status model
Source of truth = brand_story_versions.status. The landing card derives its status from the "winning" version per client (the one most representative of the current state). The card's dropdown writes back to that same row, so the landing page and the per-version editor never disagree.

Winning-version priority (used for both the thumbnail picker and the status surface):

live › approved › in_review › in_progress › not_started ·then· version_number DESC

When a client has zero versions, the legacy design_status row is used for both read and write (so the dropdown remains usable before any version exists).

04 · Editor — module add controls
Four direct module-type buttons (one-click add) plus a bulk control: count × type → Add N. All adds (single and bulk) route through a single atomic PATCH so optimistic React state can't race the server's position sequencing.
  • Quick-add buttons: Brand ASIN & Store Showcase, Brand Focus Image, Brand Logo & Description, Brand Q&A.
  • Bulk: number input (default 7) + type select (default Brand Focus Image) + Add button. The label reflects the effective count (clamped to remaining room out of 19).
  • Max: 19 modules per version. The Add button disables when there's no room left.
05 · Data layer
TableRole
brand_story_versions One row per V## per client. status is the source of truth for the landing card.
brand_story_modules Position-ordered modules (1..19) for a version. Type is one of four: asin-showcase, focus-image, logo-description, qa.
brand_story_assets Image-slot binding. kind = 'screenview' is the V##'s hero image, surfaced on the landing card.
brand_story_asin_items Children of asin-showcase modules (1..4 per module).
brand_story_qa_items Children of qa modules (1..3 per module).
drive_files The drive_file_id (text) column on this table is the actual Google Drive GID — what the /brand-story-image proxy understands. The brand_story_assets FK points to drive_files.id (uuid), not the GID.
06 · API contract
EndpointNotes
GET /api/design-status Returns one row per active client with brandStoryVersionCount, brandStoryThumbnailUrl (or null), and a brand_story category status derived from the winning version when one exists.
PUT /api/design-status For category = 'brand_story', mirrors the new status onto the winning version's brand_story_versions.status. Falls back to design_status upsert only when zero versions exist.
GET /api/design-status/brand-story-versions Per-client list of versions, with assets stitched (screenview, bg_desktop, bg_mobile) and modules with their typed children.
PATCH /api/design-status/brand-story-versions/[id] Atomic per-version save: backgrounds, alt text, and the full modules array (used by both single-add and bulk-add).
GET /api/design-status/brand-story-image?driveFileId=... Drive-content proxy. Param is the Drive GID (text), NOT the brand_story_assets.drive_file_id (uuid FK).

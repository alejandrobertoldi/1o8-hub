Overview & vocabulary

The SEO Manager is a multi-phase pipeline that converts an Amazon brand brief + ASIN list into a fully optimized listing bundle: titles, bullets (4 versions), product description, backend search terms, A+ Module 7 premium Q&A, and an audit score. Each phase has its own DB artifact, its own UI surface, and (where applicable) its own Claude prompt.

Phase model

Phases are defined in src/lib/seo/phases/s1.ts through s9.ts as PhaseExecutor objects with loadContext, fillSlots, and persist methods. S7/S8/S9 are stubs in the new executor model; the working S7 content generation lives in the legacy route src/app/api/seo/claude/seo/route.ts.

S0Competitive intake

Optional pre-pipeline skill that grounds S7 content in a competitive positioning analysis.

Source: src/lib/seo-skill-runner.ts Model: claude-haiku-4-5-20251001 Calls Claude: yes Persistence: seo_settings KV (competitive:<projectId>)

S0 is a "skill" run on-demand from the project page, gated by skill_config.s0_competitive in seo_settings. It analyzes the brand's existing ASIN content against the user-provided competitor list and saves a CompetitiveResult object. The result is read back by S7 (loadCompetitiveData at src/app/api/seo/claude/seo/route.ts:544) and injected as a COMPETITIVE INTELLIGENCE (S0 Analysis — use to differentiate content): block into every batch prompt.

S2Keyword tiering

Classify every keyword by priority tier, search intent, COSMO relationship, and PPC semantic group.

Source: src/lib/seo/phases/s2.ts + src/app/api/seo/claude/keywords/route.ts Model: configured via ai-config.server (seo_keywords feature) Calls Claude: yes (batched, parallel) Batch size: 100 keywords Persistence: seo_keywords

FieldSourceNotes

competitorsseo_projects.competitorsUsed to identify competitor-brand keywords.
guidelinesseo_projects.brand_guidelines (truncated to 600 chars)Brand context for audience/intent signals.

Processing

  1. UI sends up to 400 keywords (200 product + 200 competitor) to POST /api/seo/claude/keywords.
  2. Route splits into batches of 100, then dispatches Promise.all — all batches run in parallel to fit Vercel's 60-second window.
  3. Each batch gets the same system prompt and a batch-specific user prompt with a tier budget hint (max ceil(8 / batches) T1, ceil(15 / batches) T2).
  4. Claude returns short-key JSON (t/v/tier/int/loc/mt/cos/bs/n/sg/neg/nc/ic); the route expands them to long-form column names.
  5. On JSON parse failure for a batch, the route tries to close at the last }. If still failing, that batch returns empty.
  6. Phase persist (src/lib/seo/phases/s2.ts) deletes existing keywords for the project, then bulk-inserts the new tiered rows into seo_keywords.

Override rule in plain English

Listing wins over Group wins over Variation — checked per field, not per object.

For each of the 5 fields (messagingAngle, targetAudience, keyFeatures, doList, dontList) the resolver walks Listing → Group → Variation and returns the first non-empty array it finds. Empty/missing means "fall through." There is no merge — once a tier wins for a field, that tier's whole array is used.

Brand is not in this override chain. Brand voice is a separate free-text block that rides alongside the resolved Variation/Group/Listing block in the Claude prompt — both are present, neither overrides the other. See the "How the cascade reaches Claude" subsection below.

Per-field resolution flow

Each field walks its own path. The diagram below shows all 5 fields evaluated independently — a single ASIN can pull different tiers for different fields in the same generation.

Field ① Check Listing → ② Check Group → ③ Check Variation → Result
messagingAngle Listing? non-empty → use Listing  ·  else Group? non-empty → use Group  ·  else Variation? non-empty → use Variation  ·  else field omitted
targetAudience ↑ same walk, independent of any other field
keyFeatures ↑ same walk
doList ↑ same walk
dontList ↑ same walk

No merging. No accumulation. First non-empty tier wins the whole field's array and lower tiers are dropped for that field.

The algorithm (source)

Implemented in resolveGuidelinesFieldByField() at src/lib/variation-guidelines.ts. The function is small enough to print in full:

src/lib/variation-guidelines.tsexport type ContentGuidelines = {
  keyFeatures?: string[];
  messagingAngle?: string[];
  targetAudience?: string[];
  doList?: string[];
  dontList?: string[];
};

function pickArray(
  ...tiers: (string[] | null | undefined)[]
): string[] | undefined {
  for (const v of tiers) {
    if (Array.isArray(v) && v.length > 0) return v;
  }
  return undefined;
}

/**
 * Resolves effective guidelines field-by-field across up to 4 tiers.
 * Each field independently picks the highest-priority non-empty value:
 *   listing → group → variation → (caller falls back to brand voice if null returned)
 */
export function resolveGuidelinesFieldByField(
  listing:   ContentGuidelines | null | undefined,
  group:     ContentGuidelines | null | undefined,
  variation: ContentGuidelines | null | undefined,
): ContentGuidelines | null {
  const result: ContentGuidelines = {
    messagingAngle: pickArray(listing?.messagingAngle, group?.messagingAngle, variation?.messagingAngle),
    targetAudience: pickArray(listing?.targetAudience, group?.targetAudience, variation?.targetAudience),
    keyFeatures:    pickArray(listing?.keyFeatures,    group?.keyFeatures,    variation?.keyFeatures),
    doList:         pickArray(listing?.doList,          group?.doList,         variation?.doList),
    dontList:       pickArray(listing?.dontList,        group?.dontList,       variation?.dontList),
  };
  return isGuidelinesPresent(result) ? result : null;
}

/** Renders ContentGuidelines as a plain-text block for Claude prompts */
export function renderGuidelinesBlock(gl: ContentGuidelines): string {
  const lines: string[] = ["## Variation Content Guidelines"];
  if (gl.messagingAngle?.length) lines.push(`Messaging angle: ${gl.messagingAngle.join(", ")}`);
  if (gl.targetAudience?.length) lines.push(`Target audience: ${gl.targetAudience.join(", ")}`);
  if (gl.keyFeatures?.length)    lines.push(`Key features: ${gl.keyFeatures.join(", ")}`);
  if (gl.doList?.length)         lines.push(`Do: ${gl.doList.join(", ")}`);
  if (gl.dontList?.length)       lines.push(`Don't: ${gl.dontList.join(", ")}`);
  return lines.join("\n");
}

Key properties:

  • Field-by-field, not all-or-nothing. Each of the 5 fields (messagingAngle / targetAudience / keyFeatures / doList / dontList) is resolved independently. A listing can override only messagingAngle and inherit the rest from group or variation.
  • Empty equals not-set. Empty arrays and empty strings count as "not set" — they fall through to the next tier.
  • Arrays are picked wholesale. When a tier wins for a list field, the entire array from that tier is used — arrays are not merged across tiers.
  • Brand can now ride this function as an optional 4th tier (Phase A 2026-05-29). Free-text brand_guidelines is still passed separately into SOURCE FACTS, but if a structured ContentGuidelines brand object is supplied as the 4th arg it acts as a tier-0 fallback for fields no higher tier sets. resolveGuidelinesWithTiers() returns both the resolved object and a tier map for prompt provenance.

⚠ Only first ASIN's group + listing used per batch
